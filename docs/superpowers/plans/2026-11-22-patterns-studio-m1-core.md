# Agentic Patterns Studio, Milestone 1 (Core): Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A locally runnable web app (`python -m agentic_solutions.web`) that runs the four existing agents in **offline mode**. Each pattern shows an animated execution trace, a chat or trigger console, and its Pattern Guide.

**Architecture:** One FastAPI process serves the static no-build UI and a JSON API. A run is a `POST` whose response is a Server-Sent Events stream of trace events, produced by `graph.astream(stream_mode=["tasks","messages"])`. Graphs are compiled once at startup with a SQLite checkpointer, and they get their LLM through an injected factory: a scripted fake in this milestone.

**Tech Stack:** Python ≥3.11 (the venv has 3.14), LangGraph 1.2, langchain-core, FastAPI, uvicorn, langgraph-checkpoint-sqlite + aiosqlite, Starlette `SessionMiddleware` (itsdangerous), pytest + httpx `TestClient`. Frontend: plain ES modules, Cytoscape.js + dagre, marked + DOMPurify from pinned CDN URLs.

**Spec:** `docs/superpowers/specs/2026-11-22-agentic-patterns-studio-design.md`. Executors read both documents.

**Milestone scope:** this plan covers spec §13 milestone 1 only. Live mode, the unlock flow, budgets, rate limits, CSP and deployment are **milestone 3**, and patterns 5–7 are **milestone 2**, each with its own plan. In this milestone `GET /api/session` always reports `mode: "offline"`, `live_available: false`.

## Global Constraints

- Existing behaviour must not change: `pytest` keeps all 16 current tests passing **without editing them**, and every `python -m agentic_solutions.agents.*` CLI works as before.
- Each agent lives in its own folder under `agents/` and exports a compiled `graph`. Shared code goes in `common/`. Web code goes under `src/agentic_solutions/web/`.
- Every router function annotates its return type as `Literal[...]` (spec §5, topology rule).
- Tests make no network or API calls. Use the scripted or fake models and the fake encoder pattern from `tests/test_secure_chat_graph.py`.
- Trace event types and field names follow spec §5 exactly: `run_started`, `node_started`, `token`, `tool_call`, `tool_result`, `node_finished`, `edge`, `interrupt`, `run_finished`, `error`. Add the single field `resumed: bool` on `node_started` (spec §5, edges).
- Messages are serialized as `{role, content, tool_calls?, name?}`. Strings longer than 4 KB are cut for display, with a trailing `…`.
- Message input is at most **2,000 characters**, and a run times out after **90 s**.
- Error events carry safe text only: never a stack trace and never an environment value.
- Threads are UUIDs generated by the server and owned by the session that created them. Another session gets **404**.
- The frontend loads scripts only from `cdnjs.cloudflare.com` or `cdn.jsdelivr.net/npm/`, with exact pinned versions, and has no build step.
- Pattern ids: `qa`, `chat_loop`, `guardrail`, `human_in_loop` (and in M2: `react`, `reflection`, `plan_execute`).
- Commit after every task. The repo has no global git identity, so commit with `git -c user.name="$(git log -1 --format=%an)" -c user.email="$(git log -1 --format=%ae)" commit ...` and end messages with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`. Never stage `README.md`'s pre-existing unrelated edits until Task 11, and never stage `.env`.

## Review Focus

1. **Reloading the page mid-conversation, or after a server restart.** `GET /api/threads/{tid}/state` must return the messages in order plus the pause payload, and the UI rebuilds the console from it. A thread id unknown after a restart returns 404, and the UI silently starts a New chat. Tests in Task 8 and Task 10.
2. **Closing the tab mid-stream.** The client disconnect must still clear the session's active-run flag. Otherwise every later run returns 409 for good. Test in Task 8.
3. **A message sent after the chat has ended** (the user typed `stop`, or a trigger thread already ran). It must get a clear 409 (`"conversation ended"`), not a LangGraph error from resuming a finished graph. Test in Task 8.
4. **Empty or whitespace-only input.** Chat patterns route back to `ask` and pause again without calling the LLM. Trigger patterns reject it with 422 before any run starts. Tests in Task 6 and Task 8.
5. **HTML or script in user input or model output.** The chat never renders it as HTML: console text goes through `textContent`, and the Guide's Markdown is passed through DOMPurify. Test in Task 10.

### Task 4: `ScriptedChatModel` (offline LLM: text and streaming)

**Files:**
- Create: `src/agentic_solutions/web/offline/__init__.py`, `src/agentic_solutions/web/offline/model.py`
- Test: `tests/test_offline_model.py`

**Interfaces:**
- Produces:
  - `@dataclass(frozen=True) Rule(match: str | Callable[[str], bool], reply: str)`. A `str` match means a case-insensitive substring of the latest human message.
  - `@dataclass(frozen=True) Script(rules: tuple[Rule, ...], fallback: str)`
  - `ScriptedChatModel(BaseChatModel)` with the fields `script: Script`, `latency: tuple[float, float] = (0.3, 0.9)` (seconds before the first token), `tokens_per_second: float = 40.0`, and `matched_rule: int | None` (the index of the last rule used, or `None` when the fallback was used). It implements `_generate`, `_stream` and `_llm_type`. Latency in the sync path uses `time.sleep` (spec §9a: the sleep runs in the worker pool and holds a thread no longer than the simulated latency). The stream yields word-sized `AIMessageChunk`s.
- M2 extends this class with `bind_tools` and `with_structured_output`. Don't add them now.

**Files:**

**Interfaces:**
- Consumes: the Task 1 `build_graph` signatures, Task 3 `graph_topology`, and Task 4 `Script`/`Rule`/`ScriptedChatModel`.
- Produces:
  - `@dataclass(frozen=True) BuildContext(llm_factory: LLMFactory, checkpointer: Any, guard: ThreadGuard | None)`
  - `@dataclass(frozen=True) PatternSpec` with the fields `id`, `title`, `summary`, `mode: Literal["chat","trigger"]`, `build: Callable[[BuildContext], CompiledStateGraph]`, `start_input: Callable[[], Any] | None` (chat: the input that primes the thread to its first pause, `{"messages": []}`; trigger: `None`), `make_input: Callable[[str], Any]` (chat: `Command(resume=text)`; trigger: `{"messages": [("user", text)]}`), `output: Callable[[dict], str | None]` (the text for the trigger result card, or `None`), `explanation_path: Path`, and `samples: tuple[str, ...]`.

- Titles, summaries and modes come from spec §2 and §4.3–4.6. `chat_loop` and `guardrail` pass `ask_node=interrupt_chat_agent.graph.ask`.
